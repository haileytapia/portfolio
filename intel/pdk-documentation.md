# PDK documentation
{: .no_toc }

August 2023 – February 2024
{: .fs-5 : .fw-300 }

{: .important }
> The documentation described on this page was created for Intel and contains proprietary information. I can't share the original documentation or direct work samples, so this page provides a high-level description of the work instead.

I documented process design kits (PDKs) for five semiconductor vendors, integrating vendor software and documentation into Intel's chip design flow.

## What I worked on

Each PDK brought together hundreds of pages of information engineers needed to work with a specific vendor's software within Intel's design environment. Because the content varied by vendor, I used DITA conditional text in Oxygen XML Editor to manage vendor-specific information within a shared documentation structure.

I oversaw two PDKs from ideation through launch. Working with specifications from more than 120 engineers, I incorporated changes through two-week documentation sprints and used Visio, Acrobat, and SharePoint to create and manage supporting content.

## A different kind of technical writing

This was my first experience with semiconductor design. Each PDK contained highly specialized technical information at a scale I hadn't encountered before. I wasn't expected to become an expert in the underlying engineering of each vendor, so my role was less about developing deep subject matter expertise and more about managing the information that engineers provided. I spent much of my time figuring out how information fit together, where it belonged, and how to keep it consistent as the technical requirements changed.

Through this experience, I learned that technical writing isn't always about mastering the subject matter well enough to explain it from scratch. Sometimes, the writer's job is to bring structure to information that comes from different engineers and keep that structure intact as the documentation evolves.
