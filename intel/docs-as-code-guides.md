# Guides for docs-as-code migration
{: .no_toc }

January 2024 – February 2024
{: .fs-5 : .fw-300 }

{ .important }
> The documentation described on this page was created for Intel and contains proprietary information. I can't share the original documentation or direct work samples, so this page provides a high-level description of the work instead.

I created four GitHub how-to guides to help senior technical writers transition to a docs-as-code workflow and incorporated them into the department handbook.

## What I worked on

The team was still authoring documentation in Oxygen XML Editor, but they had started using Git and GitHub to manage documentation changes. I created four guides to help writers get started with the new workflow:

+ **Getting set up:** Creating a GitHub account and getting access to the team's repositories.
+ **Setting up the workspace:** Cloning the repositories and configuring your local environment.
+ **Editing documentation:** Making documentation changes in the GitHub-based workflow.
+ **Submitting work:** Creating PRs and submitting documentation changes for review.

## Learning docs as code

This was my first hands-on experience with docs as code, and I learned by teaching. As I created the guides, I had to learn an unfamiliar Git and GitHub workflow well enough to explain it clearly to experienced writers. This experience gave me a solid foundation in version control and collaborative documentation, which helped me get up to speed quickly in the fully docs-as-code environment at Microsoft.
